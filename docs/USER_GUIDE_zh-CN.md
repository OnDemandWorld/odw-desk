# ODW Desk 使用手册（非技术版）

> 本手册面向**不写代码的同事**：客服人员、客服主管、运营和管理员。
> 不需要任何编程知识，读完就能上手。

---

## 一、这是一套什么系统？

ODW Desk 是一套**智能客服系统**。把它想象成一位"7×24 小时在线的机器人客服 + 一套人工客服工作台"：

```
客户提问 ──► AI 机器人先回答 ──► 回答不了？──► 转给人工客服处理
（微信式聊天）     （秒回）              （带上完整聊天记录）
```

客户可以从三个渠道联系你们：

| 渠道 | 客户在哪里发消息 |
|------|------------------|
| **WhatsApp** | 手机 WhatsApp，和平时聊天一样 |
| **网页聊天** | 官网右下角的聊天小窗口 |
| **邮件** | 发邮件到你们的客服邮箱 |

所有聊天记录都保存在**你们自己的服务器**里，不会交给外部第三方，适合对数据隐私有要求的行业。

### AI 机器人会做什么？

1. **秒回常见问题**：根据你们提供的"知识库"（产品说明、常见问题文档）自动回答。
2. **保护隐私**：自动识别客户消息里的手机号、身份证号等敏感信息并打码，避免敏感数据外泄。
3. **说客户的话**：客户用中文问就用中文答，用英文问就用英文答。
4. **知道自己不行**：当它没有把握时（比如复杂投诉），会**自动转人工**，不会瞎编答案。
5. **守规矩**：管理员可以设置"红线"（例如不许承诺退款、不许谈论竞品），机器人会遵守。

## 二、如果你是客服人员

### 2.1 我每天要做什么？

当 AI 机器人把对话转给你（或你主动接管）时，你在"收件箱"里处理。打开系统后你会看到：

- **待处理列表**：所有还在进行中的客户对话。
- **未读提醒**：客户发来新消息时，对话会标出未读数量。
- **AI 摘要**：每条对话显示最后一条消息的预览，不用点开也能大致了解情况。

### 2.2 处理一条对话的完整流程

1. **打开对话**：点击列表中的对话，查看完整聊天记录（包括之前 AI 回答的内容）。
2. **接管对话**：点击"接管"（Take Over）。从这一刻起，由你来回复，AI 不再插话。
3. **回复客户**：在输入框写好回复发送，消息会通过客户原来的渠道（WhatsApp / 网页 / 邮件）送达。
4. **解决问题后**：点击"解决"（Resolve）结束这条对话。

> 💡 **小提示**：客户之后又发来消息怎么办？
> 不用担心——已解决的对话会**自动重新打开**，客户的追问不会丢。

### 2.3 什么情况下会"轮到我"？

- AI 没有把握回答（比如问题超出知识库）；
- 客户明显不满意、要求人工（发火、投诉）；
- 对话超过时限还没有人回复（SLA 超时），系统会自动把对话标记为"已升级"并通知在线客服。

### 2.4 其他实用功能

| 功能 | 用处 |
|------|------|
| **点赞/点踩** | 对 AI 的回答点 👍/👎，帮 AI 越变越聪明 |
| **按状态筛选** | 只看"进行中"或"待处理"的对话 |
| **搜索** | 用客户的电话号/名字快速找到历史对话 |
| **数据看板** | 主管可查看对话量、AI 解决率、人工工作量等统计 |

## 三、如果你是管理员

### 3.1 第一次开通：四步设置向导

系统提供"设置向导"，按顺序完成即可：

1. **连接 WhatsApp**：填入 Meta 官方下发的访问令牌和电话号码 ID（这步需要一次性找 IT 协助）。
2. **配置 AI 模型**：
   - **本地模型**（推荐起步）：数据完全不出门，适合隐私要求高的场景；
   - **云端模型**（OpenAI 等）：更聪明，但需要填 API 密钥（系统会**加密保存**，放心）。
   - 也可以两者都用：简单问题用本地、复杂问题用云端，省钱又稳妥。
3. **连接知识库（Vault）**：把你们的产品文档、FAQ 导入，AI 才能回答专业问题。
4. **激活许可**：填入 license key 激活对应版本（免费版/付费版/企业版）。

### 3.2 日常可调的配置

| 配置项 | 是什么意思 | 建议值 |
|--------|-----------|--------|
| **信心阈值** | AI 达到多少把握才敢直接回答，低于就转人工 | 0.7（先保守） |
| **品牌人设（Persona）** | 让 AI 用你们的语气说话：正式还是活泼、常用语、"必须做/不许做"清单 | 上线前配置一次 |
| **回复政策（Policies）** | 红线规则，例如检测到"退款"关键词就先发安抚模板或转人工 | 按业务需要 |
| **PII 保护开关** | 是否开启敏感信息打码 | 保持开启 ✅ |
| **SLA 时限** | 客户等多久必须有人回复（首响）和解决 | 按服务水平承诺设置 |

### 3.3 数据合规（处理客户投诉"删掉我的数据"时用）

欧洲隐私法规（GDPR）赋予客户两项权利，系统一键支持：

- **导出数据**：输入客户编号，系统生成一份该客户的全部聊天记录文件。
- **删除数据**：
  - **匿名化**（默认）：聊天内容被抹去个人信息，统计数据保留；
  - **彻底删除**：聊天和客户资料全部清除。

每次导出/删除都会自动写入**审计日志**——日志像账本一样一页扣一页（哈希链条），任何篡改都会被立刻发现，可用于合规审查和出具报告。

## 四、客户视角：他们会看到什么？

- WhatsApp 客户：像加了一个"官方客服号"，随时发消息，大多数问题秒回。
- 网页访客：点击网站聊天按钮，直接开聊，不需要注册登录。
- 邮件客户：正常发邮件，收到的是正常回信（只是回信的是 AI）。
- 如果客户问的问题 AI 答不了，会收到类似这样的回复：
  > "您的问题我已转给人工客服，同事会尽快跟进。"

## 五、常见问题（FAQ）

**Q1：AI 会说错话吗？**
有可能。所以它有"信心评分"——没把握就转人工，不硬答。你们还可以设置红线政策兜底。建议上线初期多看"点踩"记录，持续完善知识库。

**Q2：下班后客户发消息怎么办？**
AI 全天候自动回复，先安抚客户；转人工的对话会留在收件箱，第二天上班处理即可。

**Q3：客户消息会不会泄密？**
系统自带 PII 保护（自动打码敏感信息），且数据都存在你们自己的服务器。若配置了云端模型，也只有在安全策略允许的情况下、脱敏后才会发出。

**Q4：怎么知道 AI 表现好不好？**
看数据看板：AI 独立解决率、转人工率、客户满意度（CSAT 评分）一目了然。

**Q5：网页聊天和 WhatsApp 的记录是分开的吗？**
不是。同一个客户的对话会按渠道分别建立会话，但都出现在同一个收件箱里统一处理。

**Q6：系统坏了/断网了怎么办？**
消息不会丢：客户发来的消息会先完整存入数据库；外部服务（如 AI 引擎）暂时不可用时，系统会自动降级并向客户致歉，恢复后继续处理。
